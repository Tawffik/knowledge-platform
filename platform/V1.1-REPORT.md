### Paths (contract fix items 2, 7, 9)

| Contract operation | v1.1 behaviour |
|---|---|
| `GET /projects` (`skill`, `status`) | JSON list of contract Projects. Previously served the HTML page. |
| `GET /projects/{slug}` | ProjectDetail (Project + evidence[] + metrics[]). Slug enforced with `Path(pattern="^[a-z0-9-]+$")` → invalid slugs now fail validation with **422**, not an incidental 404; unknown valid slugs still 404. |
| `GET /knowledge` (`q`, `label`) | The Intel Vault in KnowledgeEntry shape, with a real verification-label filter. Invalid label → 422. |
| `POST /knowledge` → 201 | **New.** Inserts into `vault_entries`; missing source_url/checked_at or an invalid verification label → 422 via Pydantic. |
| `GET /ledger` (`project`) | The contract's lab **run log** (new `run_ledger` table). See the clash resolution below. |
| `POST /ledger` → 201 | **New.** `run_command` is required → a run without it is rejected 422 (was 405). |
| `POST /reviews` → 201 | **New.** New `reviews` table; `reason` is required and must be non-blank, reviewer/decision are enums → violations are 422 (was 404). |

The HTML pages that collided with the contract paths moved to
`/ui/projects` and `/ui/ledger` (nav links updated); `/` and `/vault`
did not collide and did not move. All v1 `/api/*` endpoints are untouched.

### Schemas (contract fix items 3–6)

- **Project** — `title` is served from the existing `name` column (no DB
  rename); `skills` is split from the stored CSV into a JSON array;
  `status` is translated at the contract boundary: `live→active`,
  `proposed→wip` (DB values and the v1 API keep the v1 vocabulary; the
  contract's `archived` is supported and currently matches no rows).
- **attribution** — new first-class column on `projects`. Seeded/backfilled
  for Agentic-Bug-Hunter, promoted out of its free-text note: it names
  AwareXone, states the repo is officially marked as a fork, and flags the
  pending branding cleanup. Other projects leave it null (optional in the
  contract) rather than inventing origin claims.
- **Evidence** — new `evidence` table implementing the schema
  field-for-field. Seeded with one `doc` evidence per project that has a
  repository (13 rows): the repo URL itself, `recorded_at` 2026-11-25,
  noted as verified in the 2026-11-25 project audit. Projects without a
  repo (7, incl. the local-only vault and the proposed projects) honestly
  return an empty evidence list for now.
- **MetricRun** — new `metric_runs` table implementing all 8 required
  fields (incl. `run_command`, `pass_fail_criteria`,
  `declared_failing_cases`) and returned from ProjectDetail as `metrics`.
  **Intentionally unseeded:** no locally documented run exists with a
  grounded command + pre-declared criteria, and inventing one would break
  the platform's evidence rule. The table fills as real runs are recorded.
- **VerificationLabel** — new `verification` column on `vault_entries`
  replaces the 0/1 flag's semantics on the contract surface (the integer
  stays for v1). Interim mapping per CONTRACT-GAPS fix 6: source-verified
  rows → `documented`; nothing seeded claims `tested`. POSTed entries
  store their label directly and keep the v1 `verified` int in sync
  (`untested`→0, otherwise 1).
- **KnowledgeEntry** — `checked_at` added (seeded 2026-11-25, the vault
  verification date), `body` served from `summary`, `tags` stored as a
  JSON array (seeded from each entry's category) and round-tripped as an
  array. **Kind:** the write side accepts exactly the contract's four
  kinds. The read side also serves the vault's own `payout` and `tip`
  rows under their real kinds — a declared local extension (CONTRACT-GAPS
  fix 6, second option), because hiding 30 of 73 verified entries would
  be worse than naming them honestly. One deviation: `source_url` is
  nullable on the read model — 3 of the 73 seeded rows (1 writeup, 1 tip,
  1 research) were parsed from vault files that cite an index instead of
  a direct URL, and a required field would 500 the whole list endpoint.
- **ReviewRecord(In)** — implemented as specified; the contract defines
  no GET for reviews, so the surface is write-only, as specified.

## Ledger name clash — resolution

The word "ledger" named two different domain objects: the contract's
**lab run log** (`project_slug, action, result, run_command, ran_at`) and
the local **Zero Track Lab bounty-outcome ledger** (`candidate_id,
gate_verdict, program_verdict, bounty…`). Neither is a superset of the
other, and renaming either would break a counterparty (his suite, or the
v1 frontend + `/api/ledger` consumers).

**Choice (least destructive): keep both, disambiguate by home.**
- Contract run log → new `run_ledger` table, served at the contract's
  root paths `GET/POST /ledger`, exactly as his contract specifies.
- Bounty-outcome ledger → stays exactly where v1 put it: `ledger_entries`
  table, `/api/ledger`, page at `/ui/ledger`.
- The distinction is documented in code comments (`app/db.py`,
  `app/routers/contract_api.py`), in `app/main.py`'s API description, and
  in the README's API table.

Suggested follow-up for Instinct (his side, not done here): a one-line
note in the contract README that `/ledger` means the run log and the
bounty-outcome ledger lives at `/api/ledger`, so "ledger" stops being
ambiguous in joint documents.

   from memory.

   files). Resolving them means opening the indexes and pinning the
   direct links — a vault-curation task, not a code task.
4. Contract `status=archived` has no local counterpart rows yet; the
   mapping is implemented and returns an empty list.
5. Nothing is published or hosted — local only, per the owner's standing
   decisions. GitHub was read, never written.
